# EpochParticleEngine v0.2.2

v0.2.2 fixes the Particle Studio process remaining alive after its window was closed, which kept the executable and build directory locked against deletion.

## Root cause

The window-close event and Vulkan shutdown callback completed, but the pinned platform runtime could remain blocked while joining its dedicated Win32 driver worker. The public Windows build wrapper also allowed reusable MSBuild worker nodes to remain alive after a build.

## Fixed

- The interactive context now pumps window events and owns Vulkan lifetime on the application thread.
- `on_stop` synchronously destroys any context still alive after a fatal or early-stop path.
- Vulkan teardown performs one device-idle wait through renderer destruction instead of waiting once in the callback and again in the destructor.
- Visual Studio builds pass `/nodeReuse:false`, preventing new reusable MSBuild workers from retaining build-tree handles.

## Validation

The release candidate passed:

- a deterministic reproduction of the original post-close process hang;
- five consecutive `WM_CLOSE` cycles, each exiting in under one second;
- exclusive read/write opening of the lab executable immediately after every exit;
- a strict MSVC Vulkan Release rebuild;
- the complete deterministic CPU test suite; and
- PowerShell parsing plus repository whitespace/version checks.

Release assets contain the source archive and its portable SHA-256 checksum.
